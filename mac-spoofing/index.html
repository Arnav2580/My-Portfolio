What is a MAC Address?

A MAC (Media Access Control) address is a 48-bit identifier permanently assigned to every network interface card (NIC) by its manufacturer. Unlike IP addresses, which are assigned dynamically by network infrastructure, MAC addresses are embedded at the hardware level and are intended to be globally unique. The address is expressed as six pairs of hexadecimal digits separated by colons or hyphens — for example, 52:6C:1E:3B:8A:4F — giving a total address space of approximately 281 trillion unique values.

The address is split into two parts: the first 24 bits (3 octets) form the OUI (Organizationally Unique Identifier), which identifies the manufacturer and is registered with the IEEE. The remaining 24 bits are assigned by the manufacturer to uniquely identify each device within their product line. The IEEE maintains a public registry mapping OUI prefixes to their corresponding organizations, making it possible to identify the vendor of any NIC from its MAC address alone.

MAC addresses operate at Layer 2 of the OSI model — the Data Link layer. Every packet transmitted on a local network contains the source and destination MAC in its frame header, and network switches use MAC address tables to forward traffic only to the correct port. Unlike IP addresses, MAC addresses are not routed across networks; they are only relevant within a single broadcast domain (local network segment). This layer-2 scope is both their strength as a local identifier and a fundamental constraint on their security utility.

The Problem — Why MAC Filtering Fails

How MAC Filtering Is Supposed to Work
  • Device connects to Wi-Fi access point
  • Router reads the device's MAC address from the 802.11 frame header
  • Router checks MAC address against its Access Control List (ACL)
  • If MAC matches → access granted. If not → connection rejected.
What Actually Happens with Spoofing
  • ⚠️ Attacker passively listens — authorized MAC addresses are broadcast in cleartext in every 802.11 management frame. No connection needed.
  • Attacker clones authorized MAC into kernel using macchanger
  • Spoofed device connects to Wi-Fi access point
  • Router reads spoofed MAC — it matches ACL entry. Attacker gains access.
  • Network granted to attacker. Event appears identical to legitimate device.
